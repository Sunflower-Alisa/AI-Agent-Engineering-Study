## Tool Calling

工具调用机制与实现



### 问题

#### 1、为什么Agent需要Tool？
LLM本身只能处理输入和生成输出，它没有访问外部世界状态的能力，也没有执行外部操作的能力。Tool为Agent提供了感知环境和执行动作的接口，是Agent能够获取实时信息、调用外部系统，并根据反馈继续决策。
Tool有两个作用：
1、扩展能力——即感知能力：让Agent获取信息
2、执行能力——即行动能力

Agent需要Tool，是因为LLM只具备语言推理能力，不具备实时感知和执行能力。Tool作为Agent连接外部世界的接口，让Agent能够获取信息、执行动作，并通过反馈完成复杂任务。
（即：LLM像人类的大脑；Tool则像人类的身体（四肢、五官等），但不仅限于身体，是Agent与外部世界交互的接口，是可以通过动态增加、替换的能力模块）

#### 2、为什么不能让LLM直接计算？
1、可靠性问题：LLM是概率模型，可能会生成一个看起来合理但错误的答案
2、成本高，消耗算力，具体的执行内容不需要大数据检索，也不需要思考，是一个固定的任务内容，就像流水线上的某一个步骤。如果都使用LLM，成本高
2、速度慢，LLM属于是我们的大脑，大脑不可能做所有的事情，而且全部在大脑里做了，会阻塞，越来越慢

不应该让LLM处理所有任务，因为LLM擅长理解、推理和决策，而不擅长高精度、确定性的执行任务。计算、查询、数据库操作等应该交给专用工具，以提高准确性、降低成本和提升速度。

#### 3、Tool结果如何进入上下文？
过程：Tool执行——>Tool返回Observation——>加入Agent State——>进入下一轮LLM Context——>LLM继续推理
ool执行后的返回结果会作为Observation加入Agent状态，并通过消息结构重新注入LLM上下文。由于上下文窗口有限，工程中通常需要使用Context Engineering，对Tool结果进行过滤、压缩、总结和结构化处理，保证LLM获得有效信息。

#### 5、Tool 为什么不只是普通函数？
普通函数：代码主动调用；
Tool：由 LLM 自主决策调用
Tool 附带标准化 Schema（描述、参数），提供 “自然语言→函数” 的映射，模型看得懂函数作用
Tool 执行结果会重新送入 LLM 上下文，形成闭环循环；普通函数执行完毕无法自动反馈给大模型
Agent 具备权限控制、轮次限制、异常捕获，Tool 是智能体可自主选择使用的外部能力。


#### 6、LLM 如何决定什么时候调用 Tool？
1.系统提示词 + Tool Schema 告知模型自身能力边界
2.LLM 推理时判断：当前信息不足以回答问题，需要外部能力（计算、查时间）
3.模型输出结构化tool_use块，而不是自然语言；由程序识别并触发执行
4.如果现有信息足够直接回答，则直接输出文本，不触发工具。


#### 7、工具结果如何进入下一轮推理？
1.Python 代码执行工具，拿到返回值，组装成标准 tool_result 消息
2.将工具结果追加进全局 messages 对话上下文
3.Agent 再次发起一轮 LLM 请求，完整上下文（历史对话 + 工具返回）全部传入
4.LLM 基于观测到的工具结果继续思考，继续选择调用工具或者输出最终答案。


#### 8、Agent Loop 极简流程（Observe → Think → Act → Answer）
1.plaintext
用户提问 
→ Observe(接收输入)
→ Think(LLM判断)
    ├─ 需要工具 → Act(执行工具) → 结果重新加入上下文，回到Think
    └─ 不需要工具 → Answer(输出最终回答，循环终止)
