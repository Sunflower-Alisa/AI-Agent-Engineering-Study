# Memory

## 分类

### 1.工作记忆（Working Memory）
LLM 当前能够看到的 Context

特点：
生命周期只有一次调用
保存在 Context
每次调用都会重新构建

### 2.短期记忆（Short-term Memory）
当聊天越来越长时，LLM 不可能一直带着全部历史。

历史聊天
↓
Memory.retrieve()
↓
找出和当前问题有关的信息
↓
放入 Context
↓
LLM回答

### 3.长期记忆（Long-term Memory）

作用：保存跨Session的信息。

长期记忆不会自动进入 Prompt。
平时不会全部发送。
只有需要时：触发retrieve("名字")
才返回：Alex
然后放进 Context。


## 三者关系
             Long-term Memory
                    │
             retrieve()
                    │
                    ▼
             Working Memory
               (Context)
                    │
               LLM 推理
                    │
                回答用户

## 问题

### 1、为什么需要Memory？
LLM本身没有长期记忆，每次调用都是独立的。如果不保存历史，模型无法记住用户的信息和偏好

### 2、Memory和Context的区别
Memory是存储
Context是当前一次调用发送给LLM的内容
Memory不会自动进入Context
只有retrieve（）后，才会加入Prompt
Memory → Retrieve → Context → LLM


### 3、为什么不能把全部历史交给 LLM？
原因有三个：
#### ① Context Window 有限制
虽然 GPT-5 能处理很长上下文，但不是无限。
#### ② Token成本越来越高
#### ③ 干扰推理
LLM 最怕：无关信息，会降低推理效果

Agent会根据当前任务，从Memory中检索有关信息，再构建Context


Memory——更像是数据库，负责长期存储信息
Context——更像工作台，只做当前任务需要的资料
LLM不直接读取数据库，而是通过Agent检索Memory，，将相关内容加入Context后再进行推理
